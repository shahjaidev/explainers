nanochat exp000

A small language model trained to a five-minute wall-clock budget rather than a step count. Every rung of the ladder gets the same seconds on the same hardware and is scored on the same validation stream, so a change that makes a step cheaper is rewarded with more steps and a change that makes a step better is rewarded directly — both land in one number.

One tree is the entire experiment

priml holds every value that affects a run in a single config tree, and nothing outside it — no environment reads, no module-level constants, no staging at build time. That means the run can be inspected before it exists. What follows is the real output of exp000().pprint(), which prints only the fields that differ from the class defaults, condensed here where eight identical transformer blocks repeat.

1

One block template, broadcast — and the copies carry their index

The experiment sets num_layers = 8 and writes a single block. finalize() copies it eight times and stamps depth onto each, because initialization scales with depth. The list is what actually prints, so the tree shows the model that will be built rather than the shorthand that described it.

2

The two mechanisms under test are both switched off here

window_pattern='L' means every layer attends over the full context, and no layer reads a value embedding. exp000 is the bar, not the proposal: a plain transformer that the ladder's additions have to beat before their complexity is earned.

3

Initialization is a value, not a flag

The output projection carries its own init — partial(normal, std=0.001) — as a callable sitting in a slot. Swapping it is assigning a different function, so nothing upstream has to learn a name for the alternative.

4

Two optimizers, split by a predicate over parameter names

NorMuon takes every tensor of rank ≥ 2 except the embedding and the head; AdamW takes the complement. The split is written as excluding(NorMuon.eligible_tensor, 'embed', 'lm_head') and its complement(…) — comparable objects rather than closures, so the config still equals its parent and still prints. Orthogonalized updates suit the matrices; the lookup tables keep a conventional optimizer.

5

The stopping clock and the annealing clock are the same clock

step.time_budget_sec is what the trapezoid schedule anneals over; max_time is what stops the loop. They are set equal deliberately — if they differed, the run would decay its learning rate against one budget and stop on another, landing short of zero or past the end. max_time_kind='train' excludes eval passes, and budget_warmup_steps=10 excludes the first ten steps, which carry the compile.

6

Geometry is declared once and verified at load

The loop's finalize() pushes vocab_size and max_seq_len from the model down onto the dataset, and the batch size down from the step. The loader then checks the prepared arrays against them. Two independently typed copies would agree only by luck — and disagree somewhere deep inside a forward pass.

The ladder

Each rung is one line

Every later experiment calls a named parent and changes one thing. These are real difflib outputs between the finalized trees, with the run-identity and path lines removed — what remains is the entire experimental delta.

exp001 forks exp000 windowed attention

Three layers in four attend over half the context instead of all of it. Most layers resolve local structure, so the accuracy given up should be small — and under a fixed budget the time saved returns as more steps. It wins if the extra steps buy more than the narrower attention costs.

- window_pattern='L' # back to the default 'SSSL'
exp002 forks exp001 value embeddings

Alternating layers read a dedicated embedding of the input tokens through a per-head gate, so a head can decline it. A deep stack's residual stream is increasingly processed; a layer that wants the raw token identity would otherwise have to reconstruct it.

+ value_embedding_stride=2 + value_embedding_layers=[1, 3, 5, 7] # derived by finalize()

The second line of exp002's diff is worth a pause: the experiment sets a stride, and finalize() derives the layer indices. A fork that changes the depth still gets alternating layers, rather than indices computed against a stack that no longer exists — and the derived value prints, so what the run will actually do is visible without running it.

This machine

What actually ran, and how it differs

The reference recipe above assumes a GPU and the ClimbMix corpus. This session has neither: four CPU cores, no accelerator, and a network policy that blocks huggingface.co and download.pytorch.org. Two substitutions were needed, and both are visible rather than silent.

A number measured here is a rehearsal, never a result

priml requires Results: to be measured on reference hardware, and the corpus below is not the corpus the ladder is defined against. The run demonstrates the machinery end to end — it does not score the experiment.

Because that is a fork and not a set of command-line overrides, it prints, diffs, and can be rerun — which is the whole argument the library makes. It lives in its own study directory, nanochat_cpu, so a rehearsal number can never be mistaken for a reference one.

One real bug surfaced on the way

The eval loader pads a short final batch and marks the padding with -1 targets, which BitsPerByte excludes from both of its sums. But NanoChatTrainStep._per_token_loss passes those labels straight into cross_entropy with no ignore_index, so the padded batch raises IndexError: Target -1 is out of bounds before the metric that handles it ever runs. It fires whenever the eval row count is not a multiple of eval_batch_size. Choosing a batch width that divides the split exactly avoids it and still scores every row.

The run

91 steps, and the schedule landed on zero

The budget expired at progress=0.9955 with the learning rate annealed to 0.0000 — the invariant the config encodes, working: because the schedule's horizon and the loop's stop condition read the same clock, the decay finishes exactly when the run does, neither short of zero nor past the end.

The clock is the experiment, so the machine is part of the apparatus

An earlier attempt at this same config reached only 50 steps before its budget ran out; this one reached 91. Nothing in the tree changed — the first run shared four cores with other work, so each step cost 1.6 s instead of 0.8 s. That is precisely why priml requires a result to be measured on reference hardware: under a fixed-time budget, contention does not add noise to the score, it changes how much training the score is measuring.

Reproduce

Three commands

from a clean checkout
# 1. Prepare the corpus once: download, fit an 8 192-token BPE vocabulary,
#    pack documents end to end into fixed-length rows.
python -m priml.baselines.nanochat.scripts.prepare_data

# 2. Verify the install end to end — minimum size, ten-second budget.
python -m priml priml.baselines.nanochat.experiments.exp_smoke

# 3. Train.
python -m priml priml.baselines.nanochat.experiments.exp000

A fourth command is the one you reach for most: exp000().pprint(). It finalizes a copy of the tree and prints only what differs from the defaults, so comparing two experiments is the same call on each, run through difflib — which is exactly how the ladder diffs above were produced.
