Agentic RL · search

How easy is it to RL a search model?

Take a 20B open model, six tools, a 238k-chunk corpus of SEC filings and a recall-weighted reward, and run synchronous Dr. GRPO through Tinker for 24 updates. Held-out F4 goes from 0.166 to 0.42, for a few hundred dollars. The surprise is what moved the needle most: not a better reward, but a 0.1 penalty for mis-formatted tool-call headers. This page is an anatomy of the repo behind the write-up, then eight ideas to build on it.

The setup

One query, six tools, one curated set

The task is Harness-1's SEC retrieval subagent task: a multi-clue question whose answer needs 3, 5 or 7 evidence facts, each fact satisfiable by any of a few interchangeable chunks. The agent never answers. It searches, reads, and builds a curated set of chunk IDs, and that set is the entire output. gpt-oss-20b with a rank-32 LoRA is the policy; the harness is deliberately thin.

The corpus is not the full 2.1M-chunk Harness-1 dump. prepare-sec keeps every gold chunk, its same-filing neighbours within ±4 positions (hard distractors), and a stable random 60k background sample, indexed in SQLite FTS5. Query families are split so no train and dev query share a gold chunk. Click a tool for its parameters and the description the model actually sees.

The loop

Synchronous, fresh-rollout Dr. GRPO

Nothing exotic. Every update samples fresh trajectories from the current weights, scores them with the terminal reward, centres each query's eight rewards on their own mean, and takes one importance-sampling policy-gradient step. No value model, no KL penalty, no standard-deviation normalisation (that is the "Dr." in Dr. GRPO: dividing by a group's std would over-weight queries where the rollouts nearly agree).

Draw a batch

64 queries in a fixed difficulty interleave, so every batch spans 3-, 5- and 7-fact tasks and the hard ones are not exhausted early.

Roll out ×8

Eight independent 40-turn episodes per query against the live FTS5 index, parallel tool execution, temperature 1. Sampling is 90%+ of wall-clock.

Score

Terminal reward on the curated set: F4 against the fact groups, minus flat penalties. Timeouts and context overflows still get partial credit.

Centre & filter

Advantage = reward − group mean. Groups where all eight rewards are equal carry no gradient and are dropped before the step.

One step

Importance-sampling loss, lr 1e-4, one substep, save every update. Sixteen updates is one epoch; a resumed half-epoch on reshuffled queries gets to 24.

The recipe is a flat TOML file whose keys are CLI flags, which is a small thing that makes ablations honest: the three results below differ from each other by exactly one line.

The reward

F4 is almost recall, and that is the point

Precision counts curated chunks that support any fact. Recall counts fact groups covered by at least one of their interchangeable chunks. F-beta with β=4 weights recall sixteen times more than precision, because a downstream answerer can ignore junk but cannot recover a missing clue. Drag the sliders; switch β to see why F1 would train a timid curator and why a "curate everything you saw" policy still has a high ceiling under F4.

    Results

    Three recipes, one line apart

    Held-out F4 on 32 dev queries, mean of two eval draws per checkpoint. Plain F4 training triples the base score by update 24. Adding a discovery bonus for facts merely encountered helps early and then falls behind. The format penalty wins at every checkpoint and peaks at 0.424, at about 40% more cost, because clean episodes are longer episodes.

    Best-of-N as the "is this RL-able?" test

    Before training, the post samples the base model four times per eval query and compares best-of-4 to a single draw. A wide gap means the base policy already contains good trajectories that RL only needs to sharpen. That is what group-relative methods can exploit; if every rollout in a group fails identically, advantages are zero and the group teaches nothing. The eval tool keeps this built in via --tries N, reporting pooled means and per-query best-of-N.

    The finding

    The penalty that beat the shaping

    gpt-oss emits tool calls in Harmony format. There is exactly one canonical header, but the base model drifts from it in roughly a quarter of episodes: wrong channel, missing <|constrain|>, code where json belongs. The cookbook's lenient parser executes those calls anyway, so plain F4 training never sees a reason to stop, and locks the drift in. Subtracting 0.1 once per episode whenever any header is off-form drives the rate to near zero, and eval F4 rises with it.

    Canonical (what the renderer itself produces)
    <|channel|>commentary to=functions.bm25_search <|constrain|>json<|message|>{"query":"Acme 10-K goodwill impairment","k":10}<|call|>
    Off-form (executed, but penalised)
    <|channel|>analysis to=functions.bm25_search code<|message|>{"query":"Acme 10-K goodwill impairment","k":10}<|call|>

    The detector is one regex over the raw sampled tokens: count to=functions. occurrences, subtract the canonical matches, and anything left is off-form. Why would a header the parser tolerates cost so much retrieval quality? Two mechanisms are plausible, and the repo does not separate them. First, drifted headers are out-of-distribution for the model's own training, so what follows them is worse (an analysis-channel call is the model calling a tool from inside its thinking). Second, the penalty acts as a cheap regulariser that keeps the policy on the base model's manifold, which is what a KL term would do, and this run has kl_penalty_coef = 0. Idea 03 below is the ablation that would tell them apart.

    The engineering

    Three patches that made the run honest and 9× cheaper

    Most of train.py and half of environment.py are monkeypatches on tinker-cookbook. None change the gradient; they change what gets counted and what gets paid for.

    Token-in, token-out

    Never re-render what the model sampled

    The cookbook rebuilds every turn's prompt from parsed messages, so a drifted header comes back canonicalised, the prefix check in trajectory_to_data fails, and each turn becomes its own training datum carrying the full context. The patch builds the next prompt as previous prompt + sampled tokens + rendered tool results, so the prefix holds by construction. One packed sequence per episode: about 9× fewer training tokens, and the policy trains on exactly the context it sampled from.

    Pre-filter metrics

    Log rewards before dropping the failures

    Constant-reward groups are removed before the step, and the cookbook computes its train metrics after that removal, which averages away the all-fail groups. The patch wraps the filter and records train_raw/* on the full batch: reward, entropy, groups dropped, fraction that curated anything. The logged train curve is then not flattered by the filter.

    Graded overflows

    Every ending is scored on the session

    A context overflow normally returns a flat reward and never calls the reward function, so a long episode with a good curated set trains on a constant. Because the reward reads the session rather than the messages, the patch grades overflows like turn-cap timeouts. Only an empty curated set gets the flat −0.2 floor, and that floor is applied last, so it deliberately overrides the format penalty.
