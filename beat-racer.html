How it's built

Every music game is the same four boxes.

Beat For Speed, Audiosurf, Riff Racer, Melody's Escape, this page — they all reduce to one pipeline. The song goes in one end, a spectrum comes out, a beat detector fires, and everything you see is some number in the world being driven by those signals. Once you see the boxes, the rest is art direction.

Audio inA decoded file, a microphone, or a synth you generate yourself. Anything that can feed an audio graph.
AnalyseAn FFT every frame. Split the spectrum into bass, mids, highs; keep a short history of bass energy.
Detect beatsA beat is a bass spike well above the recent average, with a refractory period so one kick fires once.
Drive the worldMap loudness to speed, beats to light pulses and spawns, bass to camera kick. Tune until it feels like the song.

1. The audio graph

In the browser this is the Web Audio API and it is three lines. Whatever the source is, it flows through an AnalyserNode before reaching the speakers. The analyser doesn't change the sound; it just lets you read the spectrum at any moment.

const ctx = new AudioContext();
const analyser = ctx.createAnalyser();
analyser.fftSize = 2048;               // 1024 frequency bins, ~21 Hz each at 44.1 kHz
analyser.smoothingTimeConstant = 0.4; // some smoothing, but keep transients

source.connect(analyser);              // a decoded file, a mic stream, or an oscillator
analyser.connect(ctx.destination);     // (skip this for the mic or you get feedback)

Streaming services are the one thing you can't plug in. Spotify and Apple Music are DRM-protected and never expose raw samples. That is why every game in this genre reads local files, and why the microphone option exists: it is the universal adapter for whatever is already playing in the room.

2. Reading the spectrum

Each frame, ask the analyser for the frequency data and average a few bands. Squaring the values turns the decibel-ish byte scale into something closer to energy, which makes kicks stand out more.

analyser.getByteFrequencyData(freq);         // Uint8Array, one value per bin
const hz = ctx.sampleRate / analyser.fftSize;
const band = (lo, hi) => {                  // mean energy between two frequencies
  let s = 0, n = 0;
  for (let i = Math.floor(lo/hz); i < Math.ceil(hi/hz); i++) { s += (freq[i]/255) ** 2; n++; }
  return s / n;
};
const bass = band(30, 250), mids = band(250, 2000), highs = band(2000, 8000);

3. Beat detection in fifteen lines

The obvious approach, "bass energy above its recent average", fails on real music: a sustained bass note fills the same band as the kick, so the average rises to meet it and nothing fires. The fix is spectral flux: only count how much each low bin increased since the last frame. A held note contributes nothing; a drum hit contributes a lot. Then compare that to its own recent average, with a refractory window so one kick fires once. This is exactly what the page above runs.

const prev = new Uint8Array(freq.length), history = [];   // ~45 frames ≈ 0.75 s
let lastBeat = 0;

function detectBeat(now) {
  let flux = 0;
  for (let i = 1; i < 400 / hz; i++) {          // bins up to ~400 Hz
    const d = (freq[i] - prev[i]) / 255;         // change since last frame…
    if (d > 0) flux += d * d;                    // …counting only increases
  }
  prev.set(freq);
  history.push(flux); if (history.length > 45) history.shift();
  const avg = history.reduce((a, b) => a + b, 0) / history.length;
  const isBeat = flux > avg * 1.6 && flux > 0.004 && now - lastBeat > 0.22;
  if (isBeat) lastBeat = now;
  return isBeat;
}

Real-time detection is reactive by nature: the beat fires when the kick lands, which is slightly late for spawning things the player must reach on the beat. Shipping games solve this by analysing the whole file up front (it takes a few seconds), which gives you every onset, a reliable BPM, and the song's structure before the race starts. Libraries that do this well: aubio, librosa, madmom, and Essentia. In the browser you can decode the file offline with an OfflineAudioContext and run the same loop over the full buffer.

4. Turning signals into a world

This is the part that makes it a game rather than a visualiser. Every mapping is one line, and the whole feel lives in these choices.

SignalDrivesHow
loudness (smoothed)speed of the roadtarget speed = idle + max × loudness, eased toward over ~0.7 s so it swells with the song instead of jittering
beatbuilding windows, streetlights, sky glowa pulse value jumps to 1 and decays exponentially; emissive intensity and fog colour read it every frame
beatcamera field of viewa few degrees of FOV kick on the same pulse gives the "punch" without moving anything
beatspawnsan orb appears in a random lane far enough ahead to arrive about a bar later; every sixth beat spawns a car instead
bassheadlight beam, road shimmerdirect, unsmoothed: bass is already a slow-moving signal
highsspectrum bars, star twinklecosmetic; highs are busy and look good as fine detail

The scene itself is deliberately cheap: one road plane with a scrolling lane texture, a hundred box buildings with a generated window texture as an emissive map, streetlight poles, a fence, and a sky gradient in a tiny shader. Everything scrolls toward a fixed camera and gets recycled when it passes behind. No models were loaded; the whole city is procedural.

Why the world moves and not the bike. Keeping the camera at the origin and moving the scenery avoids floating-point drift on long songs, makes recycling trivial (anything with z > 30 jumps back a kilometre), and means "speed" is just how far the scenery slides per frame.

From prototype to product

The page above is the entire idea, and it is roughly 600 lines. Going from this to something like Beat For Speed is mostly about polish and platform, not about a different design:

  • Pick an engine. Unity ships spectrum data on every AudioSource (GetSpectrumData) and has the largest pool of tutorials for exactly this genre. Godot 4 has AudioEffectSpectrumAnalyzer and exports to mobile easily. Unreal has Audio Synesthesia for offline analysis. All three let you keep the same four boxes.
  • Analyse offline, react live. Pre-scan the song for BPM and onsets so the level is built ahead of time, then use the live spectrum for lights and speed. That gives you tight rhythm gameplay and the reactive feel.
  • Generate the track from the song. Audiosurf's trick: map song energy to the road's slope, so quiet intros climb and drops plunge. Section detection (verse, chorus) gives you a place to change the city's colour palette.
  • Spend on light. The dusk look in the clip is bloom, volumetric headlights, wet-road reflections, and a strong palette, not geometry. Post-processing is where the mood comes from.
  • Music sourcing is the product decision. Local files and a microphone are the only unrestricted paths. Anything with a catalogue means licensing.
  • Make it easy to share. The clip you saw is the marketing. Build the "record a 15-second clip" button early.

Read the source of this page: the audio section, the beat detector, and the scene are three separate blocks you can lift into any project.
