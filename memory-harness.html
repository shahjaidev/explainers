The Memory Tool Harness

In filesystem-based agent memory, no agent touches the store directly. Every read and write passes through a tool harness — and the paper's sharpest finding is that this wrapper is not neutral. Swapping the tool set reshapes the memory store as strongly as swapping the model.

The setting

Three roles, one filesystem

Memory is a directory tree of markdown files under /memories, each opening with YAML frontmatter — a name slug matching the filename stem, and a one-line description that surfaces in directory listings. Two agents work on that store, and they are handed deliberately different tools.

Management agent

  • Integrates incoming content
  • Merges, splits, moves, deletes
  • Keeps the store organized
→

Tool harness

  • Function-calling interface
  • Delivered separately from the system prompt
  • The only path to the store
←

Search agent

  • Answers queries with citations
  • Read-only
  • Must navigate the organization

/memories — markdown tree, YAML frontmatter, agent-owned

The tools

Ten tools, exactly as sent

The management agent gets the six operations of the industry memory tool plus line-level regex search. The search agent gets a read-only set that answers only what the store's own names, layout, and headings expose — which is precisely how the paper forces it to navigate the organization. Click any tool for its parameters and its delivered description.

The experiment

The harness as a control knob

Hold the store variant and the model backbone fixed, run the same conversations, and change only the tools. Any difference is attributable to the harness alone.

What it means

Adding a tool ≠ replacing the tool set

Behavior vs outcome

Adding changes behavior only

Grant both roles ranked whole-file search and the search agent adopts it eagerly — 219 calls across the skills chain — while quality lands in a statistical tie (net −2, p≈0.85).

Behavior vs outcome

Replacing changes the store

A bash shell reshapes organization outright. On long dialogue it shards; on skills it consolidates hardest and wins outright (82.9%, the best mini-curated chain under any tool set).

Coupling

Search co-adapts, unprompted

BM25 gets used 54 times over a 29-file store, but twice over a single mega-file — there the agent walks the table of contents and reads sections instead. Same toolbox, different strategy.

Caution

Finer structure isn't better

Stores diverging by two orders of magnitude in file count answer about equally well. On LoCoMo the three harnesses tie at 86.1–86.7%. Shape is not quality.
