The thesis

Three axes, one architecture

Every component in K3 maps onto exactly one direction in which information is allowed to move. That framing is what makes an otherwise sprawling list of tricks legible.

Sequence → Hybrid attention

Three Kimi Delta Attention layers per one Gated MLA layer. Linear-cost recurrent mixing carries the long range; periodic global attention preserves unrestricted token-to-token reach.

Depth → Attention Residuals

A residual stream is an RNN over layers. AttnRes replaces uniform accumulation with a learned softmax over all preceding layer outputs.

Width → Stable LatentMoE

896 routed experts, 16 live — sparsity 56. Experts work in a half-width latent space so routing multiplicity stops costing full-width traffic.

Sequence axis

Kimi Delta Attention

KDA is the delta rule with a channel-wise forget gate. Each token updates a fixed-size recurrent state S ∈ ℝ^(d_k×d_v): decay the state per channel, erase the component along the current key, then write the new value.

St = (I − βt kt kt⊤) · Diag(αt) · St−1  +  βt kt vt⊤

αt is the per-channel retention factor, βt the write strength. Because the state never grows, the cost of an extra token is constant — the property the whole 1M-context story rests on.

The change that actually mattered: bounding the decay

Chunkwise KDA rescales keys inside a chunk by the reciprocal cumulative decay 1/Γ. If retention can approach zero, that reciprocal explodes past what BF16 can hold. Kimi Linear handled this with log-space arithmetic plus 16-token sub-tiles — but the diagonal tiles still needed explicit position-pair computation, and that was the intra-chunk bottleneck.

K3 swaps the unbounded negative-Softplus map for a scaled sigmoid with a floor:

Log-decay parameterisation

gmin = −5 is the whole trick

With a floor at −5 every retention factor stays above e−5 ≈ 6.7×10−3. Cumulative log-decay over a 16-token tile lands in (−80, 0), so the reciprocal rescale stays under e80 — inside BF16 range. Consequence: every causal tile, diagonal included, becomes a dense Tensor Core matmul. The special-case path disappears.

K3 also promotes KDA's output gate from Kimi Linear's low-rank form to a full-rank input-dependent projection, applied after head-wise RMSNorm.

Sequence axis, continued

Gated MLA — and no positional encoding at all

Every fourth layer is Multi-head Latent Attention: keys and values are compressed into one low-dimensional latent per token and reconstructed on the fly, so the KV cache stays small while global attention stays exact.

The interesting decision is NoPE. K3 applies no positional encoding to the MLA layers whatsoever. Position is carried implicitly by the KDA layers' recency-aware decay. The payoff is direct: extending to 1M tokens requires no RoPE base retuning, no YaRN interpolation, no positional surgery of any kind. The model simply extrapolates.

What the hybrid buys at long context

structural model — layer accounting, not measured bytes

A 93-layer all-global design pays per-token cache in every layer. K3 pays it in 24, and carries 69 fixed-size recurrent states that cost the same at 8K as at 1M. This chart counts which layers hold length-proportional state; it is a structural ratio, not a byte measurement.

Depth axis

Attention Residuals

The argument is elegant. A standard residual stream compresses everything a network has computed into one running state hl — structurally an RNN over depth, with the same bottleneck recurrence has over time. Transformers solved that bottleneck for sequences by letting each position attend. AttnRes applies exactly that move to depth.

Each layer carries a learnable pseudo-query; the outputs of all preceding layers (plus the token embedding) are keys and values, RMSNorm'd so a loud layer can't dominate. A layer reads from wherever it needs to.

Who can read whom

rows = layers · columns = sources

Full AttnRes is affordable in arithmetic — depth is under 100, so O(L²d) is nothing — but the O(Ld) cost of keeping every layer output alive is real, and worse under pipeline parallelism where those tensors cross stage boundaries. So K3 uses the block variant: 8 blocks of 12 layers, each block summed to one representation, full attention across the 9 block-level vectors (embedding included). Memory and cross-stage traffic drop from O(Ld) to O(Nd), and — the part that pays off at serving time — the inference state is bounded, letting the parallel inter-block result merge with the sequential intra-block partial sum through online softmax.

N ≈ 8 recovers most of the benefit across scales. K3's 8×12 partition leaves a partial final block, giving 9 block representations counting the embedding.

Width axis

Stable LatentMoE — and the two ways it breaks

Ordinary MoE hands every selected expert the full d-dimensional token, so doubling active experts doubles communication and weight traffic. LatentMoE splits the difference: two full-width shared experts handle common transformations, while 896 routed experts operate in a compact latent space of half the model width (3584). That is what makes 16-of-896 affordable at all.

At sparsity 56 and 2.8T parameters, two failure modes get loud. First, the routed path chains W↓ → gated multi-branch FFN → W↑ into nearly four consecutive matmuls — ill-conditioned enough to explode activations. Second, balancing ~10³ experts per layer is well outside the regime where fixed-step bias updates behave. The "Stable" in the name is three answers to those two problems.

1 · RMSNorm before the up-projection

The aggregated routed representation's scale varies with which experts fired and how they were weighted. Normalising it before W↑ desensitises the routed branch to that variation before it merges with the full-width shared branch. Beyond stability, it consistently improves validation loss.

2 · SiTU-GLU: soft-capping both factors

SwiGLU multiplies two unbounded factors, so coincident large coordinates produce outliers and overflow risk in low precision. Plain GLU's sigmoid gate is bounded but loses Swish's near-linear positive regime. SiTU-GLU applies softcap(x,β) = β·tanh(x/β) to the linear factor of the gate and, independently, to the up branch.

SwiGLU vs SiTU-GLU

β₁ = 4 (gate) · β₂ = 25 (up) · output bounded by β₁β₂ = 100

Near the origin the scaled tanh is approximately linear, so SiTU-GLU tracks SwiGLU where the activations actually live. Far out, it flattens to a hard ceiling instead of running away.

3 · Quantile Balancing

K3 uses auxiliary-loss-free routing: a per-expert bias bj is added to the router score for Top-k selection only — it never enters the mixture weights, so it steers dispatch without touching the router's gradients. DeepSeek's original rule nudges that bias by a fixed step in the direction of the load error, and the step size trades slow adaptation against oscillation. At 896 experts per layer, that trade gets bad.

QB solves for the bias directly. Route with Top-(k+1) instead of Top-k: the extra entry is the cutoff αi a token demands. The number of tokens expert j would receive under a candidate bias is monotone in that bias, so setting it to the target load q = mk/n means picking the (q+1)-th largest margin — i.e. the (1−k/n)-quantile of s:,j − α. One forward pass, closed form, applied next step so a batch is never routed by a bias derived from itself.

At real scale the margins number in the millions across ranks, so K3 reads each quantile from a histogram — one all-reduce over a few hundred bins per expert, exact up to bin width because counts are additive regardless of sharding.

Modality

Native vision, and a negative result worth stating

Text, images and video share one backbone in one context, with no post-hoc alignment stage. Rendered output and the code that produced it live in the same token stream — which is what makes vision-in-the-loop behaviour (write code, look at the screenshot, fix it) possible without a cross-model handoff.

The notable choice: MoonViT-V2 is trained from scratch with next-token prediction, not initialised from SigLIP. Standard practice assumes contrastive pre-training gives a head start. Moonshot dropped it primarily for stability — the SigLIP-initialised tower showed persistently higher gradient norms with frequent spikes under joint optimisation, while the from-scratch tower stayed flat. And it matched the SigLIP baseline across vision evals anyway.

"Contrastive pre-training is unnecessary as an initialisation for multimodal language models at scale." — a claim the field has largely assumed the opposite of.

Systems

Training infrastructure

K3 stacks three system problems that rarely co-occur: a recurrent attention formulation hostile to wide parallelism, 3T-class sparse multimodal training, and million-token agentic rollouts. Each gets a co-designed answer.

KDAMaking a serial recurrence parallel＋

FlashKDA — a CUTLASS chunkwise kernel that overlaps intra-chunk computation with cross-chunk state propagation, instead of alternating between them and leaving SMs idle during the serial phase. Work is split into token-parallel stages and a head-parallel recurrence, tuned independently. Now a backend of flash-linear-attention.

Intra-device context parallelism — tensor parallelism shards heads but never shortens the recurrence, so ultra-long prefill idles most SMs. Since each segment's state transition can be evaluated independently of the incoming state and composed exactly afterwards, an SM-level planner splits the sequence within one rank. No cross-device traffic.

KDA Context Parallelism (KCP) — the cross-device version, and the subtle one. Vanilla linear attention is additive, so ranks can just sum local states. KDA isn't: the delta rule applies a token-dependent matrix Mt to the incoming state before writing. KCP decomposes each segment into two locally computable pieces — a cumulative transition ∏M and a state generated from zero — which compose associatively, so incoming states are recovered by a prefix scan. Cost: one fixed-size all-gather, independent of sequence length.

MoonEPPerfectly balanced expert parallelism＋

Conventional EP leaves ranks unevenly loaded, which costs throughput and — because routed-expert activation shapes vary step to step — fragments memory. MoonEP forces every rank to receive exactly S×K tokens using dynamically planned redundant experts.

The load-bearing result is a proof: a balanced plan always exists with at most E/R redundant experts per rank, and the bound is essentially tight. Reserving that many slots guarantees planning never fails, so training is never interrupted. Prior schemes (ECHO, UltraEP) preset a redundancy count or a per-rank token cap, must halt when no feasible plan fits, and still leave residual imbalance.

Perfect balance then pays out three more times. Zero-copy communication: the planner precomputes every token's destination, so tokens land directly in expert-grouped positions on remote ranks and buffer views feed computation with no intermediate copies — and the buffer shrinks from S×K×R to S×K. Sync-free execution: shapes are statically known, eliminating the per-layer host↔device sync that stalls the pipeline between MoE layers. Scheduling: per-expert counts within a rank are still skewed, so a workload-aware GEMM scheduler picks parameters from an analytical cost model before launch; shared experts go to a separate stream to overlap.

MemoryFitting 2.8T into a bounded budget＋

Unified activation manager. Every tensor saved for backward gets a pluggable storage backend, so recomputation, quantisation and offload become interchangeable policies declared by annotation, composable per tensor and fully decoupled from model code. Most K3 activations use block-wise FP8 plus offload; element-wise operators are recomputed.

Memory-efficient MoE. The permuted-probs gradient normally depends on the forward output; rewriting it to depend only on the intermediate activation and upstream gradient removes that dependency for one cheap element-wise op. The group-GEMM input is recovered by recomputing dispatch, and the resulting communication hides inside the GEMM backward.

AttnRes without the memory bill. Block representations are generated once at the block boundary and shared; the whole AttnRes computation is checkpointed so per-layer saved activations match a standard residual network exactly. Pipeline stages exchange only newly generated blocks, hitting the theoretical memory floor.

Cross-rank rebalancing. Interleaved 1F1B leaves early PP ranks holding more live activations, so K3 remotely offloads activations into other PP ranks' memory over the Mooncake Transfer Engine. Gradients are ZeRO-2 sharded and parked in CPU memory.

P2P Muon. Newton–Schulz needs whole parameter matrices, but the optimizer shards them. Rather than all-gathering the entire parameter buffer on every rank, each rank pulls only the shards it owns peer-to-peer — no full-parameter buffer, less communication, pipelined against computation.

VisionHiding the encoder entirely＋

Large images and long videos make the vision tower's cost both large and wildly variable, which is poison for a synchronous pipeline. K3 shards a single large image across devices along the patch dimension with gather-KV attention, and spreads multiple large images across sub-CP groups so the communication fraction doesn't grow with scale.

Then it exploits pipeline bubbles: under interleaved 1F1B the first micro-batches' text forwards all bunch up at the start and the last micro-batches' backwards finish at the very end. ViT forwards for the first micro-batches run synchronously up front; the rest are scheduled into the bubbles. Most of the encoder's cost disappears into space that was idle anyway.

Agentic RLMillion-token rollouts on a few hundred GPUs＋

External KV cache pool. At 1M context a prefix miss is catastrophic, and partial rollouts make it worse — every iteration begins with a pile of unfinished long prefills arriving at once. K3 decouples prefix retention from GPU residency: idle reusable prefixes are written back to CPU DRAM only when evicted (not write-through), then prefetched before reuse. KDA states are offloaded and prefetched alongside their MLA blocks so lifecycles stay aligned. Training weights and optimizer states go to NVMe between iterations to free the DRAM.

Auto-throttling scheduler. Context grows as a trajectory advances, so any fixed concurrency is either wasteful early or causes preemption late. The scheduler reads active/queued request counts and KV utilisation at runtime and modulates how many requests reach the engine.

Gradient-buffer reuse. Forward-only reference models are kept in CPU memory and materialised into the policy's FP32 gradient-buffer storage — safe, because those buffers get overwritten by real gradients later. Two VPP chunk slots ping-pong: one computes while the other prefetches.

AgentENV51 million sandboxes＋

Container runtimes weren't survivable: capable agents exploring aggressively produced kernel panics and deadlocks. But clamping down would cap capability — complex tasks need environments where an agent can mount disks, run containers, even launch VMs. AgentENV runs Firecracker microVMs instead.

The lifecycle primitives are what make it an RL system rather than just a sandbox. Incremental checkpointing saves only pages dirtied since the last checkpoint: 133 ms to checkpoint, 49 ms to resume. On top of that: Pause/Resume — a paused sandbox costs nothing, and a sandbox spends up to 98% of its life waiting on model inference. Fork — clone exact state while the original keeps running, for side-effect-free reward judging. Snapshot — periodic saves for error recovery.

Density: OverlayBD images with a custom ublk driver, layer sharing and P2P transport give sub-second launch at scale; copy-on-write memory and page-cache tuning reach 6.5× memory overcommit.

Total across K3 training and evaluation: 51,219,741 sandboxes over 1,505,678 distinct images.

Production

Serving a hybrid model is its own research problem

Two cache types with incompatible shapes, brand-new modules with no existing kernels, and traffic whose per-request cost spans three orders of magnitude.

The prefix-cache granularity conflict

Block-hash prefix caching assumes one block size shared by every layer. But MLA pages per token, while KDA holds one large recurrent state per sequence — snapshots are only affordable at sparse boundaries, which forces the shared block to 1024–6144 tokens. And since hashing is tied to the storage block, hash granularity gets dragged along. At that coarseness caching is nearly useless: any request shorter than one block can never be reused, and chunked prefill exports nothing cacheable until it crosses a full boundary.

K3 decouples the two. Prefix hashing runs on fine 512-token hash blocks inside MLA pages; the physical block stays the coarse allocation unit. KDA checkpoints are saved only at a sparse subset of those same hash endpoints — the only positions a lookup could ever name.

A hit at token 2560, inside a 6144-token block

hover the hash blocks

Lookup runs in two stages. MLA matches whole physical blocks by chained hash and, at the first miss, falls back to hash endpoints inside it — so partially filled pages stay hittable. Then KDA requires a persisted checkpoint at that boundary in every KDA cache group. The hit is the longest boundary satisfying both: always a multiple of 512, never required to be a multiple of the physical block. The request resumes prefill from 2560 with zero recompute of [0, 2560).

Three consistency rules follow from concrete failure modes: every hit block is pinned across all groups before any allocation (one group's private copy must not evict another's hit); blocks allocated or registered within the current scheduling step are excluded from matching until their GPU copies land; and evicting one group's checkpoint atomically invalidates its siblings — a checkpoint is hittable in every group or in none.

Kernels

KDA decode + speculation

In-place state updates break under MTP speculative decoding: if verification rejects drafts, the state has already advanced past the last accepted token. Snapshotting per draft position would multiply state traffic at production batch sizes. Instead K3 caches only the projected inputs of draft tokens — far smaller than the state — rebuilds accepted states on-chip, and writes back only verified and bonus tokens. Replay, bonus token and next draft window share one recurrent loop in a single fused kernel.

Block AttnRes

Prefill: sequence parallelism decomposes the TP all-reduce into reduce-scatter + all-gather with the intra-block kernel between them, so each token's block representation materialises on exactly one rank. Decode: the inter-block pass runs on a side stream to overlap, and the intra-block merge + RMSNorm is fused into the preceding all-reduce.

Sparse latent MoE

Latent down-projection fused with the router into one GEMM; latent weights sharded with the output all-gather fused into the GEMM epilogue via multimem stores. At small batch the routed group-GEMMs are pure memory-bound weight streaming, so decoding uses a token-centric WarpDecode design — one warp per output neuron — subdivided into lane teams over disjoint expert subsets, with weights permuted offline to cut dequantisation cost.

Fleet scheduling

A 1M-context coding request carries a 400K-token prefix but only needs 4K of new prefill — a hit is orders of magnitude cheaper than a miss, so sessions are pinned to the cluster holding their cache. Consistent hashing assigns each session a primary and a secondary cluster, spreading failover re-prefill across the fleet instead of concentrating it. Separately, budget-based admission control gives each request class its own capacity, so a burst of million-token requests can't starve 2K-token ones.

Cyber-security: a rare disclosure

Frontier models from Anthropic and OpenAI refuse cyber tasks, making comparison infeasible — so Moonshot benchmarked against GLM-5.2 and published the numbers anyway. Tier 1 (vulnerability discovery): across dozens of deployed systems the model produced hundreds of candidates; of those human-reviewed, ~70% were genuine, including 16 previously unknown vulnerabilities across six projects — among them a remotely triggerable heap out-of-bounds write in the Linux kernel introduced by an incomplete upstream fix, and a Dirty-COW-class RDMA flaw where an earlier fix had dropped a permission check.

Tier 2 (end-to-end exploitation): 14 of 36 tasks (38.9%) versus 8 of 36 for GLM-5.2 — but 10 of those 14 come from the user-space track; on the kernel track neither model solves three-quarters. Since every task is human-solvable (~540 expert-hours for the suite), the unsolved set measures the remaining gap directly. A joint UK AISI / NIST CAISI assessment agrees: ahead of GLM-5.2, behind frontier cyber-capable models, achieving arbitrary code execution on 0 of 41 tasks.

Case studies

What it actually built

The case studies are unusually concrete, and several are self-referential — K3 optimising the kernels of its own architecture.

GPU kernel optimisation

Given a 24-hour sandbox budget per kernel: AttnRes latency 283.6 ms → 114.4 ms; DSA runtime −55.1%; KDA runtime −73.6%; over half of peak TFLOPS on MLA. Matched Fable 5 and beat Opus 4.8, GPT-5.6 Sol and GPT-5.5. An early checkpoint was already doing most of Moonshot's own kernel work during late development.

MiniTriton

A Triton-like compiler built from scratch: tile-level Python frontend and layout system, warp-level MLIR annotation layer, PTX codegen, plus a dual-mode tensor library with autograd, NCCL distributed primitives, and NN modules. Beats torch eager and torch.compile in geomean on its suite; its from-scratch tensor-core matmul reaches ~90% of measured machine roof at large shapes.

An inference chip

In a single 48-hour autonomous run, a prototype ASIC for a nano model of the same architecture — hybrid KDA + NoPE-MLA, Block AttnRes, INT4 weights. Closes timing at 100 MHz in a 4 mm² budget: 1.46M standard cells, 0.277 MiB SRAM, RTL-simulated decode above 8,700 tokens/s.

Research and knowledge work

Reproduced the I–Love–Q relations in computational astrophysics — 20+ papers reviewed, 300+ equations of state evaluated, inconsistencies in published formulas found, 3,000+ lines of Python — in about two hours against a typical one-to-two weeks. Elsewhere: a 42-year AI-ASIC industry site over 120 refinement rounds, 87 quarterly reports, 99 PDFs (11,000+ pages), 2,800+ web searches.

And, fittingly for a model whose architecture section is this dense: it produced a 3Blue1Brown-style motion-graphics explainer of its own architecture, and cut its own teaser video from 56 source clips.
